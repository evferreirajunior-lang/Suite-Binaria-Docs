Suite Binária — Initial Release

This section documents the features available in the first public release of Suite Binária. It is organized by area of the application, with practical explanations intended for both new and experienced ROM hackers.

Overview

The initial release introduces Suite Binária, a collection of tools for editing third-generation Pokémon GBA ROMs. The main window is the starting point for opening a ROM, accessing general functions and launching individual editors.

Main interface

When no ROM is loaded, the application indicates that no ROM is open and keeps ROM-dependent editors unavailable. After loading a compatible ROM, it identifies the game and displays the current ROM in the window.

The top menus are Options, Project, History, Tools, Settings, PokéAPI Data and Languages. Buttons for the individual editors are available in the central area.

Options

Open ROM (Ctrl+O) lets you choose a GBA ROM. The Recent menu remembers up to five successfully opened ROMs so they can be reopened quickly. Invalid entries are removed when selected; clearing the recent list never deletes the ROM files themselves.

Exit (Ctrl+Q) closes the application.

Projects

A Suite Binária project keeps settings specific to a ROM hack together, without embedding a full copy of the ROM in the project file.

  • Open project — Ctrl+Shift+O.
  • Create project from current ROM — Ctrl+Shift+S.
  • Save project — Ctrl+Alt+S.

This separation makes it easier to switch between projects without unintentionally carrying project-specific settings into another ROM.

History

Undo (Ctrl+Z) and Redo (Ctrl+Y) provide a general history of changes made during a session. ROM History (Ctrl+Shift+H) lets you review recorded changes.

Delta Backup (Ctrl+Shift+B) can keep only the changed parts of a ROM instead of storing another complete copy for every operation. This helps with recovery while saving disk space.

Tools

Global Reference Explorer (Ctrl+Shift+R) helps identify where Pokémon, Moves, Items and Abilities are referenced before you change them.

Free Space Manager (Ctrl+Shift+F) helps locate areas where new data can be stored. ROM Comparator / Change Inspector (Ctrl+Shift+C) compares previous and changed values.

Check ROM / Health Check (Ctrl+Shift+V) examines possible problems and questionable references without modifying the ROM.

Settings

The Settings window exposes three major groups: Free Space, Custom Types and INI Editor. Some settings affect how the application works; others describe the layout of the ROM currently open.

Free Space configuration

Free Space defines where the Suite starts looking when an edited description, image or expanded table needs a new location in the ROM.

You can choose whether unused regions are identified by 0xFF or 0x00. The Suite searches for the selected value only; it does not mix both kinds. 0xFF is the usual safer default. Choosing 0x00 raises a warning because zero-filled bytes can also be legitimate game data.

Custom Types

Custom Types lets the Suite display the names of additional Pokémon Types already implemented by a ROM hack, such as Fairy or Sound. The original Type IDs 0–17 are reserved; extra IDs can be named within the 18–255 range.

These names can appear in places such as Move Editor and Pokémon Base Stats. Registering a Type here does not add it to the game's battle engine.

INI Editor

INI Editor becomes available from Settings after a ROM is loaded. It can adjust the locations and counts of ROM structures, including tables expanded or moved by a ROM hack, so the Suite knows where to read and write.

It can also be configured to open automatically whenever a ROM is loaded. Changes belong to the appropriate ROM or project rather than all ROMs indiscriminately.

PokéAPI Data

The PokéAPI Data manager downloads and maintains external reference data used by supported editor functions. It can be opened without loading a ROM.

You can select individual datasets, recommended datasets or all available ones; download missing data, refresh selected data, pause, resume or cancel downloads, and run more than one download concurrently.

Verify integrity checks locally stored data; Clear selected removes selected cache entries without modifying the ROM. Keeping data locally reduces repeated internet requests.

Languages

The interface supports Brazilian Portuguese, English, Spanish, French and Italian. Automatic mode follows the Windows display language when supported and falls back to English otherwise. A manually selected language is remembered for future launches.

Language switching is temporarily disabled while an editor is open to prevent a window from being only partly translated. The language setting changes the application interface; it does not translate names or text inside the ROM.

Ability Editor

Ability Editor lets you view and change the names and descriptions of Abilities used by the ROM. It has an Ability selection area on the left and description controls on the right.

Selecting and finding Abilities

Choose an Ability from the list or type part of its name to find it. Ctrl+F focuses the search. The selected Ability's ID and description are displayed; the ID is informational.

Total Abilities

Total Abilities tells the Suite how many Ability records already exist. An original Gen III ROM typically has 78 entries. Expanded hacks can configure a larger total, up to the editor's 256-entry limit. Increasing the count does not create new Abilities or expand the game engine.

Renaming Abilities

Edit the name and press Rename to save it. The character/space indicator helps prevent names from exceeding the ROM's storage. Other open editors that display Ability names can refresh their lists.

Decap and Decap All

Decap changes an all-uppercase name such as INTIMIDATE into a more natural form such as Intimidate. Decap All applies the treatment across the recognized entries and requests confirmation first.

Descriptions and Length

You can edit an Ability's in-game description and press Save. Length compares the new text size with the available space. If it is too long, the Suite can find another free location and update the reference. Shared descriptions are protected to avoid changing other Abilities by mistake.

Desc. Offset and Repoint

Desc. Offset shows where the description is stored. Repoint can link it to another valid description address. For normal text editing, manual offsets are generally unnecessary: use Save and let the Suite handle relocation.

Free Space and Search

Free Space shows the configured search region; Search looks for a location large enough to hold the text. Finding an address does not itself save the description.

Import and Export

Import and Import All read Ability data from compatible JSON files. Export and Export All save one or all entries. Exports support JSON for reimporting and CSV for viewing in spreadsheets; CSV cannot be imported.

Imports are validated, can show a preview and may offer a backup. If an imported ID differs from the currently selected one, the Suite asks where to apply the data.

Unsaved changes and limits

The editor warns before discarding unfinished edits and checks data before and after writing. It edits Ability names and descriptions; it does not create new battle effects or implement an Ability's behavior.

Item Editor

Item Editor covers the names, descriptions, pictures and behavior-related parameters of the ROM's items, with a separate Item Effects window for supported effects.

Selecting and finding Items

Select an entry or search by part of its name. Ctrl+F focuses the search. The editor warns about unsaved changes before switching entries.

Total Items

The default counts include the ID 0 entry: 377 for Emerald, 375 for FireRed/LeafGreen and 349 for Ruby/Sapphire. A hack with a previously expanded table can configure up to 5,000 recognized entries. Changing this setting does not create new items.

Name, Rename, Decap and Decap All

Type a new name and use Rename to store it. Decap makes uppercase names easier to read, for example SUPER POTION to Super Potion. Decap All works across the list, preserving entries that cannot safely fit in their allocated name fields.

Item description

Edit the item's description and press Save Desc.. Length shows the space needed; if the new text is larger, the Suite can relocate it into free space. Offset displays the current location, while Repoint selects another valid one. Shared texts are protected.

Graphics: Icon and Pal

The Graphics panel previews the item's picture and shows its Icon and Pal addresses. Repoint selects existing graphics. Import Icon accepts a 24 × 24 PNG in the GBA-compatible palette format; Export Icon writes the current image as PNG.

Shared icons and repeated palettes are handled carefully, with possible reuse of matching graphics. Individual item icons are supported in Emerald, FireRed and LeafGreen; the same panel is not available for original Ruby and Sapphire.

General Parameters

These fields include Price, Pocket (where an item appears in the Bag), Hold Effect, Parameter, Field Func, Battle Func, Btl Usage, Type, Key Item Val, Bag Key Itm and Extra Param.

The Type in this area is an internal item classification, not a Pokémon's elemental Type. Unknown custom values can be preserved. The general Save button writes prices and parameters; names, descriptions and graphics have their own commands.

Index: copying another item's parameters

Index loads the general parameters of another item into the current editor as a starting point. It does not change the selected item's ID, name, description or icon, and does not write the ROM immediately.

Field Func, Battle Func and Custom...

These lists show recognized in-game functions, including those associated with medicine, PP recovery or battle items. Custom... can label an address of a function already implemented by a ROM hack. Registering its address does not create a new function in the game.

Item Effects

The separate Item Effects window exposes supported effects using readable controls: HP and PP recovery, reviving, status healing, PP Up/PP Max, evolution stones, Level-Up, battle boosts, EV/Friendship changes and other effects supported by the original format.

Save Changes or Ctrl+S writes the effects; Remove Effect removes the reference. The original supported effects area covers item IDs 13–175. Enigma Berry needs special handling. Some effects differ between Emerald and FireRed and are only editable where the ROM's engine supports them.

Import and Export items

Import INI, Export INI, Import ALL and Export ALL exchange one or several items. Despite the historical INI button labels, imports use JSON; CSV is an export-only format for spreadsheets.

Imports focus on names, descriptions and general parameters. They do not automatically overwrite the item's ID, price or image. Individual imports offer an ID choice; batch imports are checked and previewed, with a possible backup.

Saving safely

The editor checks values and addresses, warns about unsaved changes and tries not to overwrite data still used by another item. Keeping a separate backup remains recommended for expanded ROM hacks.

Trainer Editor

Trainer Editor customizes opponent trainers: their names and classes, appearance, battle settings, AI, usable items and Pokémon parties of up to six members.

Trainer list, search and IDs

Choose a trainer from the list, search by name or class, or use the decimal and hexadecimal ID fields to reach the same entry. These fields identify the trainer rather than changing its ID.

Name and Trainer Class

Name is the individual trainer's name. Trainer Class assigns a class such as Youngster or Bug Catcher. The Rename command next to a class renames the shared class name: every trainer using that class will display the new name. The Suite warns before confirming this change.

Decap, Decap All and settings

Decap adjusts all-uppercase names. Its settings gear lets you choose whether to affect trainer names only or also class names. Decap All performs batch changes and checks for pending edits first.

Appearance and Gender

The Appearance panel previews the trainer sprite and lets you select another sprite ID already in the ROM. The Male and Female options edit the trainer's stored Gender value. This panel does not import new character graphics.

Battle Music and Battle Style

Battle Music chooses a music identifier recognized by the ROM. Battle Style selects Single Battle or Double Battle. These values do not install missing music or battle systems.

AI behavior

The gear next to AI opens a window containing individual trainer AI options. The options explain the behaviors that can be enabled; Apply returns them to the trainer form, and Save Trainer writes them to the ROM.

Checking a custom AI flag does not create the corresponding behavior; the ROM's battle engine must already implement it.

Price Money and Money Rate

Price Money previews a reward calculation based on party level and class information. Money Rate shows the reward rate associated with a Trainer Class. Both are read-only in this editor.

Battle Items and Custom Held Item

Up to four Battle Items can be assigned for the trainer to use under the game's rules. Custom Held Item is a different setting: it indicates whether party members use individual held-item records.

Data Party: editing Pokémon

The team editor works with up to six Pokémon. For each member you can set Specie, Lv., an optional Held Item, the field labeled EV's and up to four custom Moves.

Despite its label, EV's in this trainer record is an internal value used to generate trainer Pokémon IVs, not the ordinary EV distribution awarded by training. Custom Moves enables explicit movesets; otherwise the ROM uses its standard level-based logic.

Adding and reorganizing the party

+ adds a member, − removes it, Dup duplicates a member, and ↑/↓ change the order. The new team can be reviewed before saving and cannot exceed six Pokémon.

Data Offset, Edit and Load

Data Offset shows where the party is stored. Edit can change the number of members, the custom item/move layout and storage location; it can search free space if needed. Load previews a party stored elsewhere and copies its data into the current editing session.

Loading another trainer's party does not automatically make two trainers share a pointer. Moved data may be preserved because it can still be referenced.

Party/Repoint preferences

The nearby settings gear configures automatic Free Space searches, confirmation prompts and certain advanced address options. For safety, use occupied addresses only if you know how the ROM stores shared parties.

Save Trainer, Reload and shortcuts

Save Trainer or Ctrl+S writes the trainer and party. Reload or Ctrl+R reloads them from the ROM. Pending changes trigger a Save / Discard / Cancel choice when switching or reloading.

Import and Export trainers

JSON exports and imports contain the trainer settings and party. Imports validate Pokémon, items, Moves and classes, warn about incompatible ROMs and prepare the values for the currently selected trainer without replacing its ID or reusing source-ROM addresses.

Protection against shared-data edits

When two trainers share party data, the Suite can move an edited team so the other trainer is not unintentionally changed. It checks writes and recommends backups for heavily modified games.

Trade Editor

Trade Editor edits Pokémon exchanges offered by in-game NPCs: requested and received species, Pokémon details, trainer data and optional expanded trade records.

Trade list and current Offset

The list displays the trades recognized in the ROM; Current Offset shows where each record is located. Original counts are 4 in Emerald, 9 in FireRed/LeafGreen and 3 in Ruby/Sapphire.

Trades Total versus Expand Trades

Trades Total tells the Suite how many trade records already exist. It does not create entries. Expand Trades really adds entries and can relocate the table when more space is needed, updating recognized references.

Adding a trade record does not place a new trading NPC on a map or write the character's dialogue and scripts. Those must be configured separately.

Changing trade order

The ▲ and ▼ buttons swap whole trade entries and write the order after confirmation. NPC scripts may refer to a trade's numeric position, so reordering can require script updates.

Requested and received Pokémon

Choose the Pokémon the NPC requests and the one the player receives. The received Pokémon can also have its own Nickname, Held Item and Ability slot. The original trade structure uses two Ability choices, not a new third Hidden Ability slot.

The Pokémon received generally follows the level of the Pokémon offered by the player, rather than using a separate editable level field.

IVs and Hidden Power

Edit HP, Attack, Defense, Sp. Attack, Sp. Defense and Speed IVs, each between 0 and 31. The Hidden Power display updates based on the chosen IVs and can show the resulting Power.

Its gear offers combinations that preserve existing IVs where possible, aim for Power 70, or prioritize high IVs (30/31) with Power 70. Apply combination updates the form but still requires Save Trade to write.

Original Trainer

The OT Name, Trainer ID, Secret ID and Gender fields identify the Pokémon's original trainer. Individual Random buttons can fill name and ID fields with alternative values. They do not change the NPC's own map identity.

Personality, Contest, Sheen and Mail

Personality (PID) is an internal value that affects certain Pokémon traits. Cool, Beauty, Cute, Smart and Tough are Contest conditions; Sheen is related to Contest preparation.

Mail ID refers to a message associated with a held Mail item. None (-1) means no Mail. Supported Mail ranges vary by game, and custom values require the necessary ROM data.

Randomize and its settings

Randomize prepares randomized fields for the current trade. Its gear lets you choose which categories may change: species, nickname, held item, Ability, IVs, OT data, Personality, Contest values, Sheen and Mail.

Select all and Deselect all are available, and preferences are remembered. The randomized result stays editable and is not written until Save Trade.

Save Trade, Reload and Help

Save Trade or Ctrl+S writes the current entry; Reload or Ctrl+R retrieves it again. The editor warns about unsaved changes and checks whether the source data was modified elsewhere.

Help explains IVs, OT IDs, Personality, Contests and Mail without changing the ROM.

Compatibility and limits

The editor handles original Emerald, FireRed, LeafGreen, Ruby and Sapphire trade structures and suitably configured expanded tables. It does not build NPC events or install extra trade mechanics.

Move Editor

Move Editor edits move names, descriptions, battle parameters, flags and the stored references associated with moves.

Select, search and Total Moves

Choose a Move or search by name with Ctrl+F. Its ID is shown for reference. Total Moves defaults to 355 entries, including ID 0, and can recognize up to 5,000 existing entries in suitably expanded hacks. Changing this count does not create Moves.

Rename, Decap and Decap All

Rename writes a new name, subject to the original space limit. Decap and Decap All transform uppercase names into natural capitalization; the batch action requests confirmation. Naming operations save separately from move parameters.

Effect, Power, Type and Accuracy

Effect selects the game routine for the Move; Power defines its base strength; Type is its elemental Type; Accuracy stores its accuracy value. Custom Type names registered in Settings may appear in the list, but choosing one does not implement it in the engine.

PP and EffectAcc

PP controls how many uses a Move has. EffectAcc is a separate value used by certain additional effects; it is not necessarily the Move's hit accuracy and may behave differently in modified engines.

Target and Priority

Target selects which opponent or group may be affected. Priority influences move order independently of Speed under the game's rules.

Category: Physical, Special and Status

Category displays Physical, Special and Status choices. In the original Gen III games, physical/special damage classification depends on the Move's Type. Per-Move classification only works if the ROM hack has implemented the necessary engine changes. Changing the Category field does not install that mechanic.

Pad Byte 1 and Pad Byte 2

These additional bytes are normally reserved or unused in ordinary editing, but some ROM hacks give them a custom meaning. Keep their original values unless you know how your project uses them.

Move Flags

Flags represent properties such as Makes Contact, interactions with Protect, Magic Coat, Snatch, Mirror Move and King's Rock, and High Critical Chance.

High Critical Chance is separately editable in the Emerald profile; FireRed, LeafGreen, Ruby and Sapphire handle the original high-critical behavior differently. A checked flag has an effect only if the ROM engine uses it.

Anim. Offset and Repoint

Anim. Offset shows the reference to a Move's animation. Repoint selects another valid animation address already in the ROM. It does not import or create animation graphics.

Descriptions and Desc. Offset

Edit a Move's text description in its own panel and use the nearby Save. Desc. Offset shows its current address; Repoint can select another. Text that no longer fits can be relocated automatically after confirmation. The special ID 0 description is not editable.

Hex Data preview

Hex Data displays a color-labeled preview of the 12 bytes of move parameters. It updates as fields change, and you may copy the numbers to another tool. It is informational and does not require editing hexadecimal manually.

Separate Save commands

The main Save writes battle parameters and flags; Rename writes the Move name; the description Save writes text; and Repoint changes specific references. These are separate operations, not one global save for the whole Move.

Import Single/All and Export Single/All

JSON exports preserve data for reuse; CSV exports are intended for spreadsheets. JSON is required for imports. Imported IDs are checked, with a selection when the source ID differs and previews for batch operations. Importing values does not install new battle effects.

Pending changes and safety

The editor warns when switching Moves or closing with unsaved changes. Addresses, names and values are checked before writes. For heavily expanded ROM hacks, verify configured tables and maintain backups.

Pokémon Editor

Pokémon Editor brings together the main tools for editing Pokémon species. It has six tabs: Sprites, Base Stats, Evolutions, Learnsets, Egg Moves and Pokédex. Each tab has its own data and save behavior.

General controls and navigation

The left-hand panel contains Pokémon selection, a search field (Ctrl+F), the Total Pokémon count and shared commands. The original recognized table has 412 entries, including ID 0 and reserved positions. Larger values can recognize tables already expanded by a ROM hack; they do not create new species.

Rename saves the species name; Decap or Decap All adjusts uppercase names. Import, Export and Save work with the currently selected tab, not every tab at once. The file format for tab-specific data is JSON.

Ctrl+S saves the active tab. Left Ctrl + Tab switches tabs. The Suite warns about pending changes when changing species or leaving the editor.

Sprites: front, back, Shiny and battle position

Main Sprites previews the Front Sprite and Back Sprite with their Normal Pal and Shiny Pal. The Offset fields show where the graphics and palettes are stored.

Import Sprite and Export Sprite

Export Sprite creates a PNG sheet of 256 × 64 pixels, with four 64 × 64 pictures for the front/back and normal/Shiny combinations. Compatible animated layouts may produce a 256 × 128 sheet.

Import Sprite reads the matching PNG layout, converts its graphics for the GBA and finds safe space when necessary. It can reuse identical graphics and protect shared palettes. This operation has its own save behavior, unlike the general JSON Import command.

Repoint and Emerald animations

Repoint changes references to existing graphics and palettes; it does not draw a new sprite. Animation (Emerald) displays animation frames and their Shiny colors, with controls such as Front Anim, Back Anim and Anim Delay. This panel is specific to Emerald.

Icon and Footprint

The small Icon supports palette previews Pal 0/1/2, PNG export/import at 32 × 64 pixels (two 32 × 32 frames) and Repoint. Footprint is a 16 × 16 picture with its own PNG Import, Export and Repoint.

Battle Sprite Position and Auto Position

Player Y, Enemy Y and Enemy Altitude change where the Pokémon appears on the battle screen. Auto Position suggests a suitable Player/Enemy alignment based on visible pixels; you can adjust it manually before using the panel's Save. It does not automatically save the new position.

Shared graphics and free space

When Pokémon share graphics or palettes, the editor attempts to preserve other species' data. Large imports may need relocation using the project's Free Space settings. Always review the preview after an import.

Base Stats: species characteristics

Base Stats controls the species' fundamental properties, not those of one individual Pokémon.

Stats and BST

Edit HP, Attack, Defense, Sp. Attack, Sp. Defense and Speed. BST displays their sum and is not a seventh editable statistic.

Catch Rate, Base Exp and Run Rate

Catch Rate participates in capture calculations; Base Exp contributes to experience rewards. Run Rate is an additional field whose behavior depends on the game or modified engine.

Type 1 and Type 2

Choose the species' Types. The list uses names such as Grass, Poison, Fire and Psychic and can display the additional Type labels registered under Settings. An extra Type still needs engine support.

Held Items and Abilities

Two Held Items and the original Ability 1/Ability 2 fields are available. Their names follow the Item and Ability tables. Hidden Ability is not an automatic third field of the original Base Stats structure.

EV Yield, Egg Groups and Growth Rate

EV Yield is the effort reward earned by defeating the species, not the EVs already held by an individual Pokémon. Egg Group 1/2 identifies breeding groups; Growth Rate defines its experience curve.

Gender Ratio, Steps to Hatch and Base Happiness

These controls offer Standard values or Custom numeric values for gender distribution, egg-hatching time and starting happiness.

Filler Bytes and saving

Filler Bytes are additional storage fields that a ROM hack may use for its own purposes. Leave them unchanged if you do not know their meaning. The active-tab Save stores Base Stats; JSON Import/Export operates on that tab. Pokédex Dex Color is edited separately.

Evolutions: methods and results

The Evolutions tab edits how and into which species a Pokémon evolves. Up to five positions per Pokémon are supported by the configured structure. Changing the EvolutionPerPKMN setting does not automatically erase data beyond the displayed positions.

Evolution methods and arguments

Known methods include level, Happiness, day/night conditions when supported, Trade, held or used Items, Attack/Defense comparisons, Personality-related outcomes and special evolution conditions. Level, Item and Evolves into fields are adjusted to the selected method.

Bank, Move, Map, Location and Value

Additional fields such as Bank, Move, Map, Location and Value can describe custom method arguments. An engine must already recognize the corresponding method; simply entering a number does not implement location- or move-based evolution.

Filler u16 and custom method settings

Filler u16 is an optional extra field in certain evolution formats, with a nearby ? help button. The settings gear can register a custom Method ID, name and meanings of its arguments. Original method entries are protected. The gear describes existing ROM-hack methods; it does not add their battle code.

Saving and files

Save or Ctrl+S writes the evolution entries of the selected species. JSON Import/Export on this tab covers evolutions only; imported values are reviewed before writing.

Learnsets: level-up, TM/HM and Tutors

The Learnsets tab has three sections: Level-up Moves, TM List and Tutors.

Level-up Moves

Each entry contains a learning Level and Move. Choose an entry, adjust either field and use Change Move. A counter and format information help identify the recognized structure and its limits.

Order, Offset/Structure and Manage...

▲/▼ reorder level-up entries; unlike merely editing a form, this can write the order immediately after validation. Offset / Structure shows the table's location. Manage... assists with resizing or relocating it using safe Free Space.

TM List

Check boxes indicate which TM/HM Moves the species can learn. Changing a species' check box is different from changing the actual Move assigned to a TM: the latter can affect the machine throughout the game.

Tutors

The Tutors list shows Moves taught by Move Tutors and each species' compatibility. Emerald, FireRed and LeafGreen have recognized tutor structures; original Ruby and Sapphire do not expose the same general-purpose tutor table. Adding an NPC tutor still requires in-game scripts.

PokéAPI and saving Learnsets

PokéAPI data can help compare level-up lists against external references. Missing Move IDs are flagged instead of replaced blindly. The tab's Save writes supported Learnsets and compatibility changes; JSON Import/Export keeps its data separate from other tabs.

Egg Moves: moves inherited through breeding

The Egg Moves tab lists Moves a species can inherit through breeding rather than learning them through levels or machines. It displays a counter and indicates when no entries are configured.

Add, Change and Remove

Add inserts a Move, Change replaces the selected entry and Remove deletes it from the editing list. These edits stay pending until the tab is saved. Duplicate or invalid Move IDs are checked.

Automatic expansion and shared tables

Automatic expansion can relocate and enlarge the Egg Moves table when it becomes too small. The editor shows capacity information and verifies recognized references, since the table is shared by multiple species. It can preserve old storage when another routine may still use it.

Expanding the Egg Moves list does not create new Moves in the engine.

PokéAPI and import/export

PokéAPI can suggest Egg Moves for review, but entries absent from the ROM are not blindly assigned to unrelated IDs. JSON Import/Export handles the current species' Egg Moves, and Save/Ctrl+S writes the final result.

Pokédex: entries and descriptions

Pokédex edits numbering, classification, color, measurements, size comparison and the species' descriptive text.

National, Regional/Hoenn and Hoenn to Nat

These fields relate species IDs to the National and Regional Pokédex. Their names and availability depend on the game. Renumbering an entry does not create a new species or expand the Pokédex.

Important: save a change to the National number before editing other entry fields. The Suite prevents combining such a change with unrelated edits that might end up written to the wrong Pokédex entry.

Species label, Color, Height and Weight

Species is the Pokédex classification, such as “Seed Pokémon,” rather than the editable Pokémon name. Color (Base Stats) is a category value stored in the species structure and managed separately from the main Stats. Height and Weight can be shown in metric and imperial units.

Size Comparison

The preview compares Pokémon size with a trainer, using Scale and Offset values for both pictures. Trainer ID selects the trainer shown in the preview; it does not replace trainer sprites across the ROM.

Descriptions, Page 2 and Repoint

Edit descriptive text using the length indicators and Offset information. ROMs with a second description page show a corresponding Page 2 panel.

Repoint prepares a different valid description address; it does not itself write the ROM. Longer or shared texts can be stored elsewhere during Save. Use automatic relocation for ordinary longer descriptions instead of choosing offsets manually.

PokéAPI and files

PokéAPI can help with species labels, color, measurements and selected descriptions. Description lookup may vary by generation, game and language. National/Regional mapping and the size-comparison data are not overwritten indiscriminately.

The tab supports JSON Import/Export and contextual Save with checks protecting the current entry.

PokéAPI: search, review and apply

PokéAPI integration is offered in Base Stats, Evolutions, Learnsets, Egg Moves and Pokédex. Sprites instead use their PNG and Repoint commands.

The PokéAPI switch enables consultation for the active tab; the nearby button can show states such as Consult, Loading, Review, Partial, Updated or Error.

Aliases and reviewing differences

The ... button manages aliases between names in the ROM and names used by PokéAPI. Review screens compare external information with local data before application. A Move or evolution method that is unknown to the ROM must not be assigned to an arbitrary game ID.

Auto-Apply, Auto-Save and F5

Where available, Auto-Apply prepares selected changes; Auto-Save allows them to be written through the tab's normal save path. Without Auto-Save, applied values generally remain drafts. F5 runs the PokéAPI action for the active tab while its mode is enabled; it does not save the entire ROM.

Local cache and custom ROM data

Downloaded datasets can be reused through the main PokéAPI Data manager. ROM hacks may have original names, IDs or mechanics that differ from external databases; those differences require review. PokéAPI is a reference source, not an engine upgrade.

Pokémon Editor: safety and compatibility

Each tab has its own save behavior. PNG imports, certain Repoint operations and some reordering commands may write separately from tab-specific JSON import drafts. The Suite checks for shared data and suspicious addresses before writing.

Support covers original Emerald, FireRed, LeafGreen, Ruby and Sapphire structures. A ROM hack with moved tables or custom battle rules may require additional configuration. Keep backups and test important changes in-game.

Wild Encounter

Wild Encounter lets you customize which Pokémon appear in each map's grass, water, Rock Smash and fishing encounters, with per-slot levels and the encounter frequency for each area.

Maps and navigation

The Maps panel lists recognized map groups and their locations. Selecting a map loads its encounter data. Map-group and map IDs distinguish similar names. Maps with invalid encounter data remain visible with warnings.

Show locations without Wild Encounter

This option adds maps with no encounter data to the visible list. It is useful when planning to add wild Pokémon to a previously empty location. Checking it changes only the list, not the ROM.

Grass, Water, Rock Smash and Fishing

Type switches between land encounters (grass and similar areas), water encounters, encounters triggered by Rock Smash and those triggered by fishing. Each Type has its own Pokémon list and encounter ratio. A missing area is identified and can sometimes be created through Add.

Slots, Min, Max and Pokémon

Each row identifies a Slot, minimum and maximum levels (Min and Max), Pokémon species, numeric species ID (No.) and a Chance. Fishing entries also indicate their Rod.

You can edit species and levels; the Suite checks that the minimum level does not exceed the maximum. Chance comes from the original slot distribution and is not directly editable as a free percentage.

Chance and slot limits

Original Gen III tables have 12 land slots, 5 water slots, 5 Rock Smash slots and 10 fishing slots. One species can appear in several slots, combining their chances. Changing a slot does not change the underlying slot-selection engine.

Old Rod, Good Rod and Super Rod

Fishing slots are split into 2 Old Rod, 3 Good Rod and 5 Super Rod slots. This division is fixed by the original game logic; replacing a Pokémon does not move a slot from one rod to another.

Encounter ratio

Encounter ratio is the base rate at which the game tries to generate encounters for that Type. It can be set between 0 and 255 using a numeric field or slider, with an approximate percentage shown nearby.

Unlike Chance, which decides which Pokémon may appear after an encounter is triggered, Encounter ratio influences how often an encounter may happen. Real outcomes also depend on the game's other rules.

Variants and special locations

Some maps have several sets of encounters. Variant chooses which one to view and edit; Altering Cave is a recognized example. Where known, the interface can display variant positions and their associated VAR values.

Saving a variant changes only the selected set. The game must already contain the scripts or logic that decide which variant to use.

Feebas and special encounter rules

Feebas in Emerald's Route 119 follows special fishing-location rules that are not described completely by ordinary Fishing slots. Editing a slot does not automatically replace all the special behavior implemented by the engine.

Add: creating encounter areas

Add prepares an encounter area of a Type that the map does not yet have. New slots are filled with valid starting values so you can edit them before saving. Add creates a draft first; it does not immediately write the ROM.

Maps without Wild headers

With the empty-map display enabled, it can be possible to create the first encounter area on a map that lacks a Wild header. During Save, the Suite can create that map entry, find safe free space and update recognized table references. Unsafe or unrecognized structures are rejected.

Remove: removing an area

Remove takes away the selected Type's encounter reference after confirmation. Old storage is preserved because other ROM data might still refer to it. In the Initial Release, removing the last Type did not physically delete an empty Wild header; that came later.

Recreate: recovering invalid entries

If a configured area has invalid addresses or corrupted encounter data, it may appear as Invalid. Recreate prepares a safe replacement elsewhere, preserving the old region. The user reviews the new slots and saves only when the result is acceptable.

Technical details

This panel shows the Wild header address, Structure status, Engine behavior, variant count and selected variant. It also lists the status of Grass, Water, Rock Smash and Fishing, with Info offset and Slots offset.

These values help with diagnostics and are not required for ordinary visual editing. Warnings explain malformed data or special engine behavior when it can be recognized.

ROM compatibility

Wild Encounter supports recognized original Emerald, FireRed, LeafGreen, Ruby and Sapphire encounter structures and attempts to locate moved or expanded tables by checking references. A custom encounter engine may need dedicated support.

Save, Ctrl+S and pending changes

Use Save or Ctrl+S to write the selected area's species, levels and encounter ratio. An asterisk (*) in the window title signals unsaved edits. Switching map, Type or Variant, or closing the window, offers Save, Discard or Cancel.

Before and after writing, the Suite checks the data and attempts to protect against overwriting changes made by other tools or leaving incomplete operations.

What Wild Encounter does not do

It does not draw maps, add Pokémon species, install new battle engines or create NPC scripts. Back up your ROM and test special encounter areas in-game.

Release note: dedicated map search with Ctrl+F, physical removal of empty Wild headers and later interface improvements belong to v0.02, not this Initial Release.
